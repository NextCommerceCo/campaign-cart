# Migrating from 0.4.x

Pages built for 0.4.x keep working: old attribute names, `nextConfig` keys and `window.next`
methods are read by the SDK's `compat/` files and marked `@deprecated` with their replacement.
This page lists what changes for a page builder. Every 0.4.43 attribute, method, event and
config key, with its live usage, is in [parity-0.4.md](../architecture/parity-0.4.md).

## Checkout

| 0.4.x                                                                                   | Now                                                                                                                                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `data-next-checkout-field="fname"`, `address1`, `postal`, …                             | Still read. New pages use the API names: `first_name`, `last_name`, `line1`, `line2`, `city`, `state`, `postcode`, `phone_number`                                                                                                                                                                                                    |
| `os-checkout-field`, `os-checkout-element`, `os-checkout-step`                          | Still read. Use `data-next-checkout-field`, `data-next-component`, `data-next-checkout-step`                                                                                                                                                                                                                                         |
| `<div data-next-address="shipping\|billing">` (SDK-drawn address)                       | Unchanged: the country's fields from i18n-rules, in its order, rebuilt on a country change. `-lang` and `-api` are not read                                                                                                                                                                                                          |
| Phone field: flag, typing mask, E.164                                                   | Unchanged: the flag (`img.next-phone-flag`, from i18n-rules) follows the address country, or the number's own once read; the number shows in its country's mask as typed and is written nationally or internationally on leaving; E.164 in `data-next-phone-e164`. The page's placeholder is kept (0.4.43 replaced it with `Phone*`) |
| US territories (AS, GU, MP, PR, VI, UM) in the state list                               | Unchanged: never offered                                                                                                                                                                                                                                                                                                             |
| Google address autocomplete (`nextConfig.googleMaps`)                                   | **Removed.** No campaign had an API key set                                                                                                                                                                                                                                                                                          |
| NextCommerce address autocomplete (`addressConfig.enableAutocomplete`)                  | Still read. Same dropdown and `pac-*` classes                                                                                                                                                                                                                                                                                        |
| Express buttons                                                                         | The order is placed without checking the form, unless `nextConfig.paymentConfig.expressCheckout.requireValidation` (with `requiredFields`) asks for checks, which now apply to the buttons. PayPal or Klarna chosen in the form gets the form's full checks and sends the shopper's details                                          |
| Coupon field and `next.applyCoupon`                                                     | Unchanged: a code that takes nothing off is not kept, and `coupon:validation-failed` fires. A code entered on an empty cart is checked once the cart is first priced; `next.applyCoupon` still answers `true` at once                                                                                                                |
| `nextConfig.addressConfig.countries` / `dontShowStates`                                 | Still read. The campaign's shipping countries come first                                                                                                                                                                                                                                                                             |
| `nextConfig.paymentConfig.expressCheckout.methodOrder`                                  | Still read. The campaign's express methods come first                                                                                                                                                                                                                                                                                |
| `sessionStorage['next-checkout-store']` (step guard)                                    | Written in the old shape on multi-step pages, under the exact key the guard script reads                                                                                                                                                                                                                                             |
| `next:prospect-cart-created` on the form                                                | Still fired. Scripts can use `next.on('user.created')`                                                                                                                                                                                                                                                                               |
| `data-trigger-on`, `data-auto-create="false"` on the form                               | Still read, deprecated: use `data-next-lead` (`email`, `phone`, `email+phone`, `off`). See [Lead capture](attributes.md#lead-capture)                                                                                                                                                                                                |
| `data-prospect-config`, `data-min-phone-digits`, `data-email-field`, `data-phone-field` | **Not read**, with a warning. Set `data-next-lead`; the address service checks the phone number; mark inputs with `data-next-checkout-field`                                                                                                                                                                                         |
| `next.getShippingMethods / setShippingMethod / getSelectedShippingMethod`               | Still there. The chosen method is `next.snapshot().cart.shipping_method`; set it with `next.actions.setShipping(id)`                                                                                                                                                                                                                 |

## Upsell and receipt

| 0.4.x                                                                                                                                   | Now                                                                                                                                                                                                                                                          |
| --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `data-next-upsell="offer"`, `data-next-upsell-action="add\|skip"` (`accept`/`decline`), `next-upsell-accept-url` / `-decline-url` metas | Unchanged                                                                                                                                                                                                                                                    |
| Offer classes `next-available`, `next-hidden`, `next-processing`, `next-success`, `next-error`, `next-skipped`                          | Unchanged                                                                                                                                                                                                                                                    |
| Duplicate-upsell modal ("Already Added!")                                                                                               | **Removed.** An offer already accepted on that page moves on without charging again                                                                                                                                                                          |
| `data-next-bundle-selector-id` on the offer (selector outside it)                                                                       | Still read. Put the `[data-next-bundle-selector]` inside `[data-next-upsell]`                                                                                                                                                                                |
| `data-next-action="accept-upsell"` buttons, `data-next-upsell-option`, `data-next-upsell-select`, `data-next-upsell-quantity`           | **Removed** (no live page uses them). Use a bundle selector with `data-next-upsell-context` inside the offer                                                                                                                                                 |
| `next.addUpsell`, `canAddUpsells`, `getCompletedUpsells`, `isUpsellAlreadyAdded`                                                        | **Removed** (only the v3 starter MV script used `addUpsell`)                                                                                                                                                                                                 |
| `dl_*` events in `window.dataLayer` / `window.NextDataLayer`, `window.NextDataLayerTransformFn`                                         | **Deprecated**, still sent. Listen with `next.analytics.on(name, fn)`: the same events under GA4 names (`dl_add_to_cart` → `add_to_cart`, `dl_purchase` → `purchase`, `dl_user_data` → `page_view`, …)                                                       |
| `dl_package_swapped`; no `dl_add_to_cart` for the default bundle, `forcePackageId`, `forceBundleId` or a redirecting add-to-cart button | **Removed** / **Fixed.** A bundle change sends `dl_remove_from_cart` and `dl_add_to_cart`; a cart filled before the page loaded sends `dl_add_to_cart` at the cart price. Filter on `first_in_session` to send one AddToCart per tab                         |
| `dl_upsell_purchase` queued in sessionStorage and sent on the next page                                                                 | Sent on the next page from the order's own lines; nothing is queued                                                                                                                                                                                          |
| `dl_purchase` `user_properties` with the customer's email, name and address                                                             | Without personal data, and without URL query strings in `page_referrer` / `attribution.metadata`. Same `transaction_id`, value and tax basis (incl. or excl. tax, picked per order as 0.4.x did), `item_sku`, per-item `discount`, `item_brand` and `coupon` |
| `order.*` display paths, `[data-next-order-items]` with `{item.*}` tokens                                                               | The paths and tokens live pages use, unchanged                                                                                                                                                                                                               |

## Events

| 0.4.x                                                                                                                         | Now                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `next.on('cart:updated')`, `coupon:*`, `checkout:*`, `order:completed`, `upsell:*`, `exit-intent:*` and the other 0.4.x names | Still sent, with their 0.4.43 payloads and at the moments 0.4.43 sent them. New scripts listen with the [Event Reference](events.md) names                                                                                                                                          |
| `checkout:started`                                                                                                            | Still sent on every checkout page; the new `checkout.started` comes once per checkout                                                                                                                                                                                               |
| `dl_begin_checkout`, `dl_add_shipping_info`, `dl_add_payment_info`                                                            | Sent once per checkout: a later step, a reload or a return from the payment gateway does not send them again                                                                                                                                                                        |
| `cart:package-swapped`, `order:redirect-missing`, `address:messages-loaded`, `upsell:accepted`                                | **No longer sent**; `next.on` warns. Package selectors are gone; the checkout always sends the shopper on; the checkout no longer loads the address service's texts; offers send `upsell:added` (0.4.43 sent `upsell:accepted` only for `data-next-action="accept-upsell"` buttons) |
| `payment:tokenized`                                                                                                           | Still sent, without `token` and `pmData`; a warning says so once a page                                                                                                                                                                                                             |
| `next.exitIntent({ image \| template })`                                                                                      | Unchanged; it also takes `id` and `name`, which reach `view_promotion` and `select_promotion`                                                                                                                                                                                       |

## Page widgets

| 0.4.x                                                                                                                                   | Now                                                                                                        |
| --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `data-next-accordion` (+ `-trigger`, `-panel`, `-text`, `data-open-text`, `data-close-text`, `data-toggle-class`, `data-initial-state`) | Unchanged, in a small chunk loaded only where it is used                                                   |
| `data-next-tooltip` (+ `-delay`, `-offset`, `-max-width`, `-class`)                                                                     | Unchanged look; placed above (or below when there is no room) without floating-ui. `-placement` is ignored |
| `data-next-i18n` (apollo-multi-variant only)                                                                                            | **Removed.** It could replace page copy with the service's text; pages keep their own words                |
| `data-next-include-shipping`                                                                                                            | Ignored, as it was in practice: 0.4.x never sent it to the API                                             |
