# `window.next`

Available after the `sdk.ready` event (`next.on('sdk.ready', fn)`, or its alias `ready`; a listener
added later gets it too).

A script that may run before the SDK, in `<head>` or from a tag manager, queues a callback in
`window.nextReady`. It is called with `window.next` once the page is ready, or at once when the
page already is. It works before or after the loader's `<script>`:

```js
(window.nextReady ||= []).push((next) => {
  next.on('order.paid', (order) => …);
});
```

A callback that throws is logged (`nextReady callback failed`); the others still run.

| Member                                                    | Does                                                                                                                                                                                                                                    |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `next.version`                                            | SDK version                                                                                                                                                                                                                             |
| `next.on(event, fn)`                                      | Listen to an [event](events.md), starting with the ones this page already sent; returns an unsubscribe function                                                                                                                         |
| `next.analytics.on(name, fn)`                             | Listen to a [tracking event](/analytics) by name, or `'*'` for every one ([Analytics](analytics-reference/how-it-works.md), [Destinations](analytics-reference/destinations/overview.md))                                               |
| `next.snapshot()`                                         | What the page shows now: `campaign`, `cart`, `checkout`, `order`, `selectors`, the same objects the events carry                                                                                                                        |
| `next.getState()`                                         | The SDK's internal state, for debugging; its shape changes between releases                                                                                                                                                             |
| `next.context()`                                          | The page, campaign, session, attribution and browser now, as on tracking events                                                                                                                                                         |
| `next.bind(root)`                                         | Bind attributes inside markup added after the page loaded                                                                                                                                                                               |
| `next.log.level`                                          | What reaches the console: `debug`, `info`, `warn` (default), `error`, `silent`; `?debug=1` starts at `debug`                                                                                                                            |
| `next.log.entries()`                                      | The last 200 SDK log entries `{ level, message, data?, at }`, whatever the level                                                                                                                                                        |
| `next.log.stream(fn, { replay? })`                        | Call `fn` with every new entry (and the earlier ones with `replay`); returns an unsubscribe function                                                                                                                                    |
| `next.query(path)`                                        | A value of the object model, as `data-next-query` reads it: `await next.query('cart.total')`. A promise: its code loads on the first call, so a page that never asks never downloads it. `next.snapshot()` has the same objects at once |
| `next.watch(path, fn)`                                    | Calls `fn` with the value once its code has loaded, then each time it changes; returns an unsubscribe function                                                                                                                          |
| `next.define(type, name, fn, { format? })`                | A field the page computes on every object of a type (`Cart`, `CartItem`, `Selector`, `Option`, `Order`, `OrderItem`), read like the SDK's own; never sent with events                                                                   |
| `next.actions.<name>({ … })`                              | Every action `data-next-action` names, with one object of the model's field names; resolves to `{ ok, errors? }` and never throws. See [Actions](#actions)                                                                              |
| `next.actions.setGroup(id, { lines, vouchers? } \| null)` | Replace (or remove) a named group of lines                                                                                                                                                                                              |

Kept for 0.4.x page scripts, each marked `@deprecated` with its replacement:
`addItem({ packageId, quantity })`, `clearCart()`, `swapCart(items)`, `applyCoupon(code)`,
`getPackage(id)`, `getCampaignData()`, `getCartData()` (0.4.x shape), `exitIntent(options)` (its
`id` and `name` options name the popup on its `promotion.*` events),
`getShippingMethods()`, `setShippingMethod(id)`, `getSelectedShippingMethod()`,
`setMetadata(values)`, `addMetadata(key, value)`, `getMetadata()`, `clearMetadata()` (on a page with
0.4.x attributes, from its ready callbacks on), and the `next:ready` / `next:initialized` window events.

The other 0.4.x members are gone; no live page calls them. [parity-0.4.md](../architecture/parity-0.4.md)
lists each one with what to use instead.

## Actions

| Action                         | Takes                                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `addItem`                      | `items` (`"1x2, 5"`), or `package_id` and `quantity`, or `selector_id` for its picked option; `replace` empties the cart first |
| `removeItem`                   | `package_id`                                                                                                                   |
| `setQuantity`                  | `quantity` (`"+1"`, `"-1"` or a number) and `package_id` or `selector_id`; `min_quantity`, `max_quantity`                      |
| `select`                       | `selector_id`, `option_id`                                                                                                     |
| `clear`                        | —                                                                                                                              |
| `applyCoupon` / `removeCoupon` | `code`                                                                                                                         |
| `setShipping`                  | `shipping_id`                                                                                                                  |
| `acceptUpsell` / `skipUpsell`  | `selector_id` or `items`: what the offer adds to the order, on a page opened with `?ref_id`                                    |
| `setCurrency`                  | `code`: opens the page again priced in that currency, when the campaign sells in it                                            |
| `go`                           | `url`: opens it with the visit's parameters                                                                                    |
| `setMetadata`                  | Any keys: each is set on the order's attribution `metadata`; `undefined` or `''` removes one                                   |

```js
await next.actions.addItem({ package_id: 42, quantity: 2 }); // { ok: true }
await next.actions.applyCoupon({ code: 'nope' }); // { ok: false, errors: { code: 'code "NOPE" was not applied' } }
```

`setMetadata` is for a value the page learns after it loaded, such as a click id or a quiz answer:

```js
await next.actions.setMetadata({ everflow_transaction_id: 'abc123', quiz_result: 'dry' }); // { ok: true }
```

A value is a string or a number, kept to 2000 characters. It stays for the rest of the browser tab
and is sent with the cart and the order, after the SDK's own keys (`landing_page`, `referrer`,
`fb_fbp`, …), so a key of the same name takes the page's value. `everflow_transaction_id` is also
the order's Everflow id, ahead of `?evclid` and `localStorage.evclid`.

The 0.5 calls `addItem(packageId, qty)`, `removeItem(packageId)`, `setQuantity(packageId, qty)`,
`applyCoupon(code)`, `removeCoupon(code)` and `setShipping(id)` still work, with their old results.

## Debugging with `?debug=1`

`?debug=1` on the page URL sends every SDK log line to the console and adds a round **N**
button in the bottom-right corner. Debug mode then stays on for every page of the browser tab,
so it follows the shopper through the funnel, and the panel opens on each page as it was left.
`?debug=0` or **Turn off debug** in the menu ends it. The button shows the number of issues on
the page; click it for a menu with the campaign, SDK version, cart, the country, currency and
language in use, a link into each panel tab and the **Developer mode** switch. The gear in the menu opens the settings:
**Page config**, **Theme** (the system's light or dark, or one picked for the
rest of the tab) and **Position** (the left or right side; the dock icon in the panel does the
same). The panel is drawn with tsugi.

**Page config** shows the page's whole `window.nextConfig` by part (Analytics, Language, Checkout,
Page), marking a value set by a 0.4.x key, tried on the tab or edited, and, on its **Code** tab, the
block written in the current keys; **Copy** and **Download .js** (`next-config.js`) take it for the
page. Its switches and fields edit that block; **Try on this tab** runs every page of the browser tab with it while
debug mode is on, and the menu says so until **Reset**. `apiKey` and `funnel` are read before the
SDK starts: they are shown, never tried, and left out of the block (put them on the script tag).

The panel starts simple: Journey, Issues, Checkout, Analytics and Events, without the codes a
developer reads. Over it float three switches for the country, currency and language in use, each marked when it
differs from the visitor's geo (hover for how); the globe in its header opens the visitor's geo. **Developer mode** adds a
**Developer** tab, named after the tool open, whose dropdown holds Elements, State, Logs, Performance, **Pick an element**
and the API, funnel and storage scope, and the detail inside the other tabs: package ids and SKUs,
the selector a cart line came from, when the cart was priced, **Raw state**, the totals formula,
and the storage scope of each page. The choice stays for the rest
of the browser tab.

Hovering an element card outlines it on the page; clicking scrolls to it. **Pick an element**
(in the menu, or in the Developer tab's dropdown), then a click on the page, shows that element and its
SDK parents; the click does not reach the page, and Esc cancels. The filter narrows elements,
analytics and logs, each tab keeping its own, and each tab opens at the top. **Reset saved data** asks for a second click, then clears this funnel's saved cart, form and order.

From the console, `nextDebug.explain(el)` gives the same for one element; with an element
selected in DevTools, `nextDebug.explain($0)`.
